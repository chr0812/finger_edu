# 01. 공통 설계

## 1. 기술 전제
- **서버 없는 브라우저 전용 앱**(발표용 데모, M10). React + TypeScript(strict) 정적 빌드(예: Vite)로 만들고 정적 호스팅 또는 로컬 실행만 한다. 외부 시스템과 통신하지 않는다.
- 데스크톱 전용: 최소 너비 1280px, 최신 Chrome/Edge. 모바일 대응 없음(D8).
- 데이터는 브라우저 `localStorage`에 저장한다. 화면 코드는 저장소를 직접 만지지 않고 **데이터 계층(`src/data/*Repo`)** 의 비동기 함수만 호출한다. 함수 시그니처·타입·저장 구조는 `90_데이터계층_및_타입.md`를 따른다.
- 데이터 계층은 업무 규칙(삭제 차단, 중복 검사, 일수 계산 등)과 입력 검증을 모두 책임진다. 화면의 클라이언트 검증은 UX용이다.
- 목록의 필터·정렬·페이지네이션은 데이터 계층에서 메모리 배열로 처리해 `Page<T>`를 반환한다.
- 비동기 상태 관리 라이브러리(예: TanStack Query)와 폼 라이브러리(예: react-hook-form + zod)는 권장이며 선택은 구현 단계 재량이다.
- 라우팅은 클라이언트 라우터(예: React Router). 탭은 URL 경로로 구분해 새로고침해도 유지한다. 정적 호스팅에서도 동작하도록 해시 라우터 사용을 권장한다.

## 2. 앱 셸 (CMN-001)

```
+----------------------------------------------------------------------------+
| MY 직원관리 [DEMO]   (회사명)  관리자이름 님  [데모 초기화] [로그아웃]    |  <- 헤더 56px
+------------------+---------------------------------------------------------+
| 직원관리         |  페이지 제목                                             |
|   직원등록       |  [탭A] [탭B]                                             |
|   조직도         |  ---------------------------------------------------   |
| 휴가관리         |  ▸ 안내 및 유의사항 (접이식)                             |
| 회사설정         |                                                         |
|                  |  (페이지 본문)                                           |
|                  |                                                         |
+------------------+---------------------------------------------------------+
   좌측 메뉴 220px                      본문 (가변)
```

| 요소 ID | 요소 | 규칙 |
|---|---|---|
| `shell.header.demoBadge` | DEMO 배지 | 항상 표시. 발표용 데모임을 나타낸다 |
| `shell.header.company` | 회사명 | `authRepo.me()`의 `company.name` |
| `shell.header.user` | 관리자 이름 | `account.name` + " 님" |
| `shell.header.reset` | [데모 초기화] | S-CMN-02(danger) "모든 데이터를 처음 샘플 상태로 되돌립니다. 입력한 내용은 사라집니다." 확인 후 `systemRepo.resetDemo()` → MSG-012 토스트, 현재 화면 재조회(로그인 상태는 유지) |
| `shell.header.logout` | [로그아웃] | `authRepo.logout()` 후 `/login` 이동. 데이터는 지우지 않는다 |
| `shell.nav` | 좌측 메뉴 | 대메뉴 3개: 직원관리(하위: 직원등록, 조직도), 휴가관리, 회사설정. 현재 경로에 해당하는 항목 강조 |
| `shell.guide` | 안내 및 유의사항 (CMN-003) | 페이지 제목 아래 접이식 영역. 기본 접힘. 문구는 각 화면 파일에 정의 |

**라우트 가드**
- 앱 진입 시 `authRepo.me()`를 호출한다. 로그인 상태가 아니면(`null`) `/login?redirect={현재경로}`로 이동한다.
- 데이터 계층 호출이 `AUTH_REQUIRED`로 실패하면(다른 탭에서 로그아웃 등) MSG-008을 토스트로 표시하고 `/login?redirect=...`로 이동한다.
- 로그인 상태에서 `/login` 접속 시 `/employees`로 이동한다.
- 존재하지 않는 경로는 "페이지를 찾을 수 없습니다" 화면과 [직원등록으로 이동] 버튼을 보여준다.

## 3. 공통 컴포넌트

### 3.1 S-CMN-01 부서선택 (CMN-006)

```
+---------------------------------------+
| 부서 선택                         [X] |
+---------------------------------------+
| ▾ ☐ (회사명)                          |
|     ▾ ☐ 개발팀                       |
|         ☐ 백엔드                      |
|         ☐ 프런트엔드                  |
|     ☐ 인프라팀                        |
|     ☐ 미배정                          |
+---------------------------------------+
|                    [취소]   [확인]    |
+---------------------------------------+
```

| 항목 | 규칙 |
|---|---|
| Props | `mode: 'multi' \| 'single'`, `selectedIds: number[]`, `includeUnassigned: boolean`, `onConfirm(result)`, `onCancel()` |
| 결과 | `{ departmentIds: number[]; unassigned: boolean }` |
| 데이터 | `departmentRepo.list()`. 트리는 `parentId`로 구성하고 `sortOrder` 순 |
| multi 동작 | 부모 체크 시 하위 전체 체크, 해제 시 하위 전체 해제. 하위 일부만 체크되면 부모는 indeterminate. 회사 루트 체크 = 전체 부서 선택 |
| single 동작 | 라디오처럼 하나만 선택. 회사 루트는 선택 불가. "미배정"은 `includeUnassigned`일 때만 선택 가능 |
| 노드 | 접기/펼치기 토글. 최초에는 모두 펼침 |
| 확인 | multi에서 선택 0건이면 [확인] 비활성. 선택 결과를 호출 측에 전달하고 닫는다 |
| 필터에서의 표시 | 호출 측 필터바에 선택된 부서명을 칩으로 표시(최대 3개 + "외 N개") |
| 빈 상태 | 부서가 하나도 없으면 "등록된 부서가 없습니다." 표시, 미배정만 선택 가능 |

**필터바 "부서구분" 패턴** (S-EMP-01, S-VAC-01, S-VAC-03 공통)
- 라디오: `(•) 전체  ( ) 부서별`. "부서별" 선택 시 [부서선택] 버튼과 칩이 나타난다.
- "부서별"인데 선택이 없는 채로 [조회]를 누르면 MSG-009를 표시하고 조회하지 않는다.
- 쿼리 파라미터: `departmentIds`(쉼표 구분), `unassigned`(boolean). "전체"이면 둘 다 보내지 않는다.

### 3.2 S-CMN-02 확인 다이얼로그
- Props: `title`, `message`, `confirmLabel`(기본 "확인"), `cancelLabel`(기본 "취소"), `danger: boolean`.
- 삭제·취소처럼 되돌릴 수 없는 동작은 `danger`(확인 버튼 강조색)로 연다.
- Esc 또는 바깥 클릭은 취소와 같다.

### 3.3 모달 규칙
- 폭 기본 560px, 본문 스크롤. 열릴 때 첫 입력에 포커스, 닫히면 호출한 요소로 포커스 복귀.
- [저장] 등 제출 버튼은 요청 중 비활성화하고 스피너를 표시해 중복 제출을 막는다.
- 입력이 변경된 상태(dirty)에서 [취소]·X·Esc·바깥 클릭을 하면 MSG-005 확인 다이얼로그를 띄운다.
- 데이터 계층 검증 오류(`DataError.fieldErrors`)는 해당 필드 아래에 표시하고 모달은 유지한다. 필드에 매핑되지 않는 오류는 모달 상단 배너에 표시한다.

### 3.4 폼 규칙
- 필수 항목은 라벨 뒤 `*`. 제출 시 첫 오류 필드로 스크롤·포커스한다.
- 검증은 blur 시 필드 단위, 제출 시 전체. 문구는 §7 메시지 카탈로그.
- 앞뒤 공백은 제출 시 제거한다.

### 3.5 데이터 테이블
- 헤더 고정, 행 호버 강조, 정렬 가능한 컬럼은 각 화면 파일에 명시(없으면 정렬 불가).
- 페이지네이션: 하단 중앙, 20건/페이지, "이전 / 1 2 3 … / 다음", 우측에 "총 N건".
- 조회 조건이 바뀌면 1페이지로 돌아간다.
- 조회 조건과 페이지는 URL 쿼리에 반영해 새로고침·뒤로가기에 복원한다.

### 3.6 토스트
- 우상단, 성공 3초 / 오류 5초 후 사라짐. 최대 3개 스택.

### 3.7 날짜 범위 필터 (CMN-004)
- 구성: `[1개월] [3개월]` 프리셋 + 시작일 date picker + `~` + 종료일 date picker + [조회].
- 프리셋 클릭: 종료일 = 오늘, 시작일 = 오늘 − 1개월 또는 − 3개월. 값만 채우고 조회는 [조회]를 눌러야 실행한다.
- 검증: 종료일 < 시작일이면 MSG-010, 366일 초과이면 MSG-011.

## 4. 공통 상태 UI

| 상태 | 표시 |
|---|---|
| 로딩(목록) | 테이블 본문에 스켈레톤 행 5개 |
| 로딩(모달 데이터) | 모달 본문 스피너 |
| 빈 결과 | 테이블 영역 중앙에 MSG-006 |

| 저장/삭제 오류 | 토스트(오류) 또는 모달 배너. `DataError`의 오류 코드에 대응하는 MSG를 표시하고, 대응이 없으면 MSG-007. 저장소 오류(`STORAGE_UNAVAILABLE`, `STORAGE_QUOTA`)는 MSG-013·MSG-014 |

## 5. 표시 형식

| 대상 | 형식 | 예 |
|---|---|---|
| 날짜 | `YYYY-MM-DD` | 2026-10-19 |
| 요일 | 한글 1자 | (월) |
| 시간 | `HH:mm` 24시간 | 09:00 |
| 휴대폰 | 하이픈 표시, 저장은 숫자만 | 010-1234-5678 |
| 일수 | 소수점 첫째 자리까지, 정수면 소수 생략 | 1, 0.5, 2.5 |
| 잔여 일수 음수 | 빨간색 | -1.5 |
| 인원수 | 정수 + "명" | 12명 |
| 값 없음 | `-` | 직책 미지정 → `-` |
| 직원 상태 | ACTIVE → "재직중", RESIGNED → "퇴사" | |
| 계약구분 | REGULAR → "정규", NON_REGULAR → "비정규" | |

## 6. 필드 검증 규칙

| 필드 | 규칙 |
|---|---|
| 이름 | 필수, 1~30자 |
| 휴대폰 | 필수, 숫자만 추출해 10~11자리이고 `01`로 시작. 입력 중 자동 하이픈 |
| 이메일 | 필수, 이메일 형식, 최대 100자 |
| 생년월일 | 필수, 1900-01-01 ~ 오늘 |
| 입사일 | 필수, 1900-01-01 ~ 오늘+365일 |
| 부서명 | 필수, 1~30자 |
| 직책명·직위명 | 필수, 1~20자 |
| 근무유형명 | 필수, 1~20자 |
| 주근무시간 | 필수, 0.5 이상 52 이하, 0.5 단위 |
| 휴일명 | 필수, 1~30자 |
| 휴가 사유 | 선택, 최대 200자 |
| 신규휴가(부여) | 필수, 0이 아닌 값, 0.5 단위, -99.5 ~ 99.5 |

화면 검증은 UX용이며 데이터 계층이 동일 규칙을 다시 검증한다.

## 9. 로그인 상태·저장소·보안 (데모 기준)
- 로그인 상태는 `sessionStorage`의 플래그로만 관리한다(탭을 닫으면 로그아웃). 업무 데이터는 `localStorage`에 있어 로그아웃해도 남는다.
- 이 앱의 로그인은 **데모 화면용**이며 보안 기능이 아니다. 데이터는 암호화하지 않고, 누구나 브라우저 개발자 도구로 볼 수 있다. 실제 개인정보를 입력하지 않는다. 화면 하단 푸터에 "발표용 데모 — 샘플 데이터만 사용하세요."를 표시한다.
- 회사는 시드된 1개뿐이며(D7) 모든 조회는 그 회사의 데이터를 대상으로 한다. 클라이언트에서 `companyId`를 선택하는 UI는 없다.
- 다른 탭에서 데이터가 바뀌면(`storage` 이벤트) 현재 화면의 목록을 재조회한다. 같은 탭에서의 동시 편집 충돌은 고려하지 않는다.
- 세션 만료 카운트다운 UI는 없다(M5).
