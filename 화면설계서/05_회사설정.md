# 05. 회사설정

회사설정은 두 탭으로 구성된다. `/settings`는 `/settings/work-types`로 이동한다. 휴가정책·급여정책·사내공지 탭은 없다(M5, M6).

---

## S-CFG-01 회사설정 — 근무유형 탭

| 항목 | 내용 |
|---|---|
| 경로 | `/settings/work-types` |
| 근거 | CFG-001, M4, M7, D18, DD-17 |

### 와이어프레임

```
회사설정
[근무유형] [휴일]
▸ 안내 및 유의사항
                                                        [+ 근무유형 추가]
+--------------------------+  +--------------------------+  +--------------------------+
| 표준근무 [기본 제공]  ⋮  |  | 시차출근A                ⋮  |  | 유연근무                 ⋮  |
| 구분      고정           |  | 구분      고정           |  | 구분      유연           |
| 출퇴근    09:00 ~ 18:00  |  | 출퇴근    10:00 ~ 19:00  |  | 출퇴근    -              |
| 주 근무시간  40시간      |  | 주 근무시간  40시간      |  | 주 근무시간  40시간      |
| 적용 직원    12명        |  | 적용 직원    3명         |  | 적용 직원    1명         |
+--------------------------+  +--------------------------+  +--------------------------+
```

### 요소 명세

| 요소 ID | 요소 | 유형 | 규칙 |
|---|---|---|---|
| `cfg-wt.add` | [+ 근무유형 추가] | button | S-CFG-02(추가) 열기 |
| `cfg-wt.card` | 근무유형 카드 | card | 유형명, 구분(고정/유연), 출퇴근시간(유연이면 `-`), 주 근무시간, 적용 직원 수. 기본 제공이면 "기본 제공" 배지. 정렬: 기본 제공 먼저, 그다음 이름 가나다순 |
| `cfg-wt.card.menu` | ⋮ 메뉴 | menu | [수정], [삭제] |
| `cfg-wt.card.edit` | [수정] | menu item | S-CFG-02(수정) 열기. 기본 제공 유형도 수정 가능 |
| `cfg-wt.card.delete` | [삭제] | menu item | 기본 제공이거나 적용 직원이 1명 이상이면 비활성+툴팁(각각 MSG-502 / MSG-503). 활성이면 S-CMN-02(MSG-506, danger) 후 삭제 |

주휴일 항목은 없다(M7). 카드는 3열 그리드.

### 동작

| 이벤트 | 결과 |
|---|---|
| [삭제] 확인 | `workTypeRepo.remove(id)` → MSG-004, 재조회. `WORKTYPE_DEFAULT_PROTECTED` → MSG-502, `WORKTYPE_IN_USE` → MSG-503 토스트 |
| S-CFG-02 저장 성공 | 모달 닫고 재조회 |

### 상태
- 로딩: 카드 스켈레톤 3개. 오류: `01_공통` §4.
- 근무유형이 하나도 없는 경우는 기본 제공 유형이 삭제 불가이므로 발생하지 않는다.

### 데이터 계층
`workTypeRepo.list()` → `WorkType[]`(적용 직원 수 포함), `workTypeRepo.remove(id)`

### 수용 기준
1. 기본 제공 "표준근무" 카드의 [삭제]는 비활성이고 툴팁에 MSG-502가 표시된다. [수정]은 가능하다.
2. 직원이 배정된 근무유형의 [삭제]는 비활성이고 툴팁에 MSG-503이 표시된다.
3. 직원 등록·수정에서 근무유형을 바꾸면 카드의 적용 직원 수가 갱신된다.
4. 유연 유형 카드의 출퇴근 시간은 `-`로 표시된다.

## S-CFG-02 근무유형 추가/수정 (모달)

### 와이어프레임

```
+------------------------------------------------------+
| 근무유형 추가                                    [X] |
+------------------------------------------------------+
| 유형명 *        [______________________]             |
| 구분 *          (•)고정  ( )유연                      |
| 출근시간 *      [09:00]    퇴근시간 *  [18:00]        |
| 주 근무시간 *   [40] 시간                             |
+------------------------------------------------------+
|                                  [취소]   [저장]      |
+------------------------------------------------------+
```

### 요소 명세

| 요소 ID | 요소 | 유형 | 규칙 |
|---|---|---|---|
| `cfg-wt-form.name` | 유형명* | text | 1~20자, 회사 내 중복 불가(앞뒤 공백 제거, 대소문자 구분 없음) |
| `cfg-wt-form.kind` | 구분* | radio | 고정(FIXED, 기본) / 유연(FLEXIBLE) |
| `cfg-wt-form.start` / `cfg-wt-form.end` | 출근/퇴근시간* | time | 고정일 때만 활성·필수. 퇴근시간은 출근시간보다 늦어야 한다(익일 퇴근 미지원). 유연으로 바꾸면 값을 비우고 비활성 |
| `cfg-wt-form.weeklyHours` | 주 근무시간* | number | 0.5 이상 52 이하, 0.5 단위 |

수정 모달은 같은 폼에 현재 값을 채운다. 기본 제공 유형은 이름 변경도 가능하다. 변경이 없으면 [저장] 비활성.

### 동작

| 이벤트 | 결과 |
|---|---|
| [저장] | 추가: `workTypeRepo.create(input)`, 수정: `workTypeRepo.update(id, input)`. 성공 시 MSG-003, 닫기, 재조회 |
| `WORKTYPE_NAME_DUPLICATED` | 유형명 필드 MSG-501 |
| 퇴근 ≤ 출근 | 퇴근시간 필드에 "퇴근시간은 출근시간보다 늦어야 합니다." |

### 수용 기준
1. 같은 이름("표준근무")으로 추가하면 MSG-501이 표시된다.
2. 구분을 유연으로 바꾸면 출퇴근 시간 입력이 비활성이 되고 저장 후 카드에 `-`로 보인다.
3. 고정에서 출근 18:00, 퇴근 09:00을 입력하면 저장되지 않는다.
4. 적용 직원이 있는 유형의 이름을 수정해도 직원의 근무유형 연결은 유지된다.

## S-CFG-03 회사설정 — 휴일 탭

| 항목 | 내용 |
|---|---|
| 경로 | `/settings/holidays` |
| 근거 | CFG-020, D23, DD-16, DD-18 |
| 쿼리 | `from`, `to` |

### 와이어프레임

```
회사설정
[근무유형] [휴일]
▸ 안내 및 유의사항
+--------------------------------------------------------------------------+
| 조회기간   [올해][내년] [2026-01-01] ~ [2026-12-31]               [조회]  |
+--------------------------------------------------------------------------+
총 21건                                                     [+ 휴일 추가]
+------------+------+------------------+----------+--------+------+
| 일자       | 요일 | 휴일명           | 구분     | 출처   |      |
+------------+------+------------------+----------+--------+------+
| 2026-01-01 | 목   | 신정             | 휴일     | 법정   |  -   |
| 2026-03-02 | 월   | 삼일절 대체공휴일| 대체휴일 | 법정   |  -   |
| 2026-11-20 | 금   | 창립기념일       | 휴일     | 추가   | [삭제]|
+------------+------+------------------+----------+--------+------+
```

### 요소 명세

| 요소 ID | 요소 | 유형 | 규칙 |
|---|---|---|---|
| `cfg-hol.filter.period` | 조회기간 | 날짜 범위 | `01_공통` §3.7의 변형: 프리셋은 [올해] [내년]. 기본값은 올해 1월 1일 ~ 12월 31일. 최대 366일(MSG-011) |
| `cfg-hol.search` | [조회] | button | 조회 |
| `cfg-hol.add` | [+ 휴일 추가] | button | S-CFG-04 열기 |
| `cfg-hol.table` | 목록 | table | 컬럼: 일자, 요일, 휴일명, 구분(휴일/대체휴일), 출처(법정/추가), 삭제. 일자 오름차순. 페이지네이션 없음(최대 366일 범위) |
| `cfg-hol.row.delete` | [삭제] | button | 출처가 "추가"인 행만 표시. 법정 행은 `-`를 표시하고 호버 시 MSG-505 |

### 동작

| 이벤트 | 결과 |
|---|---|
| [삭제] | S-CMN-02(MSG-506, danger) → `holidayRepo.remove(id)` → MSG-004, 재조회. 법정 휴일이면 `HOLIDAY_STATUTORY_PROTECTED` → MSG-505 |
| S-CFG-04 저장 성공 | 모달 닫고 현재 기간으로 재조회 |

휴일을 추가·삭제해도 이미 등록된 휴가의 사용일수는 바뀌지 않는다(DD-11).

### 상태
`01_공통` §4. 기간 안에 휴일이 없으면 MSG-006과 "시드 데이터가 없는 연도입니다. [+ 휴일 추가]로 직접 등록할 수 있습니다."를 표시한다.

### 데이터 계층
`holidayRepo.list({from, to})` → `Holiday[]`, `holidayRepo.remove(id)`

### 수용 기준
1. 2026년을 조회하면 `91` 시드의 법정휴일(대체공휴일 포함)이 일자순으로 나온다.
2. 법정 휴일 행에는 삭제 버튼이 없다.
3. 직접 추가한 휴일은 삭제할 수 있다.
4. 휴일을 추가한 뒤 휴가 등록 화면에서 해당 날짜를 포함한 기간을 선택하면 사용일수에서 제외된다.
5. 367일 이상의 기간을 조회하면 MSG-011이 표시된다.

## S-CFG-04 휴일 추가 (모달)

```
+------------------------------------------------------+
| 휴일 추가                                        [X] |
+------------------------------------------------------+
| 일자 *      [____-__-__]                              |
| 휴일명 *    [______________________]                 |
+------------------------------------------------------+
|                                  [취소]   [저장]      |
+------------------------------------------------------+
```

| 요소 ID | 요소 | 규칙 |
|---|---|---|
| `cfg-hol-form.date` | 일자* | 2000-01-01 ~ 2100-12-31. 회사의 기존 휴일(법정·추가 모두)과 같은 일자는 불가 |
| `cfg-hol-form.name` | 휴일명* | 1~30자 |

- 저장: `holidayRepo.create({date, name})`. 구분은 "휴일", 출처는 "추가"로 저장된다. 성공 시 MSG-003, 닫기, 재조회.
- 오류: `HOLIDAY_DATE_DUPLICATED` → 일자 필드 MSG-504.
- 토요일·일요일 일자도 추가할 수 있다(휴가 계산에는 영향이 없다).

**수용 기준**: 이미 있는 일자(예: 2026-01-01)를 추가하면 MSG-504가 표시된다.
