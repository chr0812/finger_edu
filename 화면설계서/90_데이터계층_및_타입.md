# 90. 데이터 계층 및 타입

서버가 없으므로 화면은 REST API 대신 **Repository 함수**를 호출한다. 이 문서가 화면 코드와 데이터 계층 사이의 계약이다. 함수 시그니처를 REST 설계와 동일한 수준으로 정의해 두었기 때문에, 이후 서버가 생기면 구현만 교체하면 된다.

## 1. 원칙

| 항목 | 규칙 |
|---|---|
| 위치 | `src/data/` 아래 `authRepo`, `employeeRepo`, `departmentRepo`, `positionRepo`, `rankRepo`, `workTypeRepo`, `holidayRepo`, `leaveRepo`, `leaveGrantRepo`, `systemRepo` 모듈. 저장소 접근(`localStorage`)은 이 계층 안의 `store.ts` 하나만 한다 |
| 비동기 | 모든 함수는 `Promise`를 반환한다(DD-21). 내부는 동기 접근이며 지연은 넣지 않는다 |
| 오류 | 규칙 위반은 `DataError`를 throw한다(§5). 화면은 `code`로 분기해 MSG를 표시한다 |
| 검증 | `01_공통` §6의 필드 규칙을 모든 쓰기 함수에서 다시 검증한다. 실패 시 `VALIDATION_FAILED` + `fieldErrors` |
| 쓰기 | 쓰기 함수는 ① 전체 DB를 읽고 ② 복사본을 수정·검증한 뒤 ③ 한 번에 저장한다. 중간에 오류가 나면 아무것도 저장하지 않는다 |
| 회사 | 회사는 1개(D7)이므로 `companyId`를 인자로 받지 않는다 |
| 감사 | 엔티티마다 `createdAt`, `updatedAt`(ISO 문자열)만 둔다. 이력 테이블은 없다(D15) |
| 날짜 | 날짜는 `YYYY-MM-DD` 문자열로 저장·비교한다. 일수 계산은 타임존 영향이 없도록 UTC 기준 날짜 산술을 쓴다 |
| "오늘" | `todayYmd()` 유틸 하나로 얻는다(테스트에서 고정 가능하게) |

## 2. 저장소 구조

| 저장소 | 키 | 내용 |
|---|---|---|
| `localStorage` | `myhr.v1.db` | `Db` 전체를 JSON 한 덩어리로 저장 |
| `sessionStorage` | `myhr.v1.session` | `{ accountId: number }`. 로그인 상태 |

- 앱 시작 시 `ensureSeeded()`: 키가 없거나, JSON 파싱 실패, `schemaVersion`이 다르면 시드(`91_시드데이터_및_발표시나리오.md`)로 새로 만든다.
- `systemRepo.resetDemo()`는 `myhr.v1.db`를 시드로 덮어쓴다. 세션은 유지한다.
- `localStorage` 접근 예외는 `STORAGE_UNAVAILABLE`, `QuotaExceededError`는 `STORAGE_QUOTA`로 변환한다.
- 다른 탭의 변경은 `storage` 이벤트로 감지하여 화면이 재조회하도록 `subscribe(listener)`를 제공한다.

## 3. 저장 스키마 (Entity)

```ts
export type YmdString = string; // 'YYYY-MM-DD'
export type HmString = string;  // 'HH:mm'
export type IsoString = string; // new Date().toISOString()

export interface Audit { createdAt: IsoString; updatedAt: IsoString }

export interface Db {
  schemaVersion: 1;
  seq: {                       // 자동 증가 카운터. 삭제해도 값을 재사용하지 않는다
    employee: number; department: number; position: number; rank: number;
    workType: number; holiday: number; leave: number;
  };
  company: CompanyEntity;
  account: AccountEntity;      // 관리자 1건 (D7, M1)
  departments: DepartmentEntity[];
  positions: MasterEntity[];
  ranks: MasterEntity[];
  workTypes: WorkTypeEntity[];
  holidays: HolidayEntity[];
  employees: EmployeeEntity[];
  leaves: LeaveEntity[];
  leaveGrants: LeaveGrantEntity[];
}

export interface CompanyEntity { companyId: 1; name: string; bizNo: string | null }

export interface AccountEntity extends Audit {
  accountId: 1; companyId: 1;
  loginId: string; password: string; // 데모용 평문. 보안 기능 아님
  name: string; email: string;
}

export interface DepartmentEntity extends Audit {
  departmentId: number;
  parentId: number | null;   // null = 회사 바로 아래
  name: string;
  sortOrder: number;         // 같은 parentId 안에서 1..n 연속
}

export interface MasterEntity extends Audit {  // 직책, 직위 공통
  id: number; name: string; sortOrder: number; // 1..n 연속
}

export type WorkTypeKind = 'FIXED' | 'FLEXIBLE';
export interface WorkTypeEntity extends Audit {
  workTypeId: number; name: string; kind: WorkTypeKind;
  startTime: HmString | null; endTime: HmString | null; // FLEXIBLE이면 null
  weeklyHours: number; isDefault: boolean;
}

export type HolidayType = 'HOLIDAY' | 'SUBSTITUTE';
export type HolidayOrigin = 'STATUTORY' | 'CUSTOM';
export interface HolidayEntity extends Audit {
  holidayId: number; date: YmdString; name: string;
  type: HolidayType; origin: HolidayOrigin;
}

export type EmployeeStatus = 'ACTIVE' | 'RESIGNED';
export type ContractType = 'REGULAR' | 'NON_REGULAR';
export interface EmployeeEntity extends Audit {
  employeeNo: string;            // '000001' 형식, 불변
  name: string; phone: string;   // 숫자만
  email: string; birthDate: YmdString;
  status: EmployeeStatus; hireDate: YmdString; contractType: ContractType;
  workTypeId: number;
  departmentId: number | null; positionId: number | null; rankId: number | null;
}

export type LeaveType = 'ANNUAL' | 'HALF';
export interface LeaveEntity {
  leaveId: number; employeeNo: string; leaveType: LeaveType;
  startDate: YmdString; endDate: YmdString;
  days: number;                  // 등록 시점에 확정 (DD-11)
  reason: string | null;
  registeredDate: YmdString;     // 등록한 날짜(오늘)
  createdAt: IsoString;
}

export interface LeaveGrantEntity {   // (employeeNo, year) 당 1건
  employeeNo: string; year: number;
  granted: number;               // 누적 부여일수, 항상 0 이상
  lastGrantedDate: YmdString;
}
```

참조 정리 규칙
- 직원 삭제 → 해당 직원의 `leaveGrants`도 삭제(DD-8). `leaves`가 있으면 삭제 불가.
- 직책/직위 삭제 → 해당 값을 가진 직원의 `positionId`/`rankId`를 null로(D19).
- 부서 삭제 → 소속 직원·하위 부서가 있으면 불가.
- 근무유형 삭제 → 적용 직원이 있거나 `isDefault`이면 불가.

## 4. 화면용 타입 (DTO)

}
// page는 1부터. 범위를 넘으면 마지막 페이지로 보정. size 기본 20.

export interface Me {

export interface EmployeeQuery {

  keyword?: string;

}
export interface EmployeeListItem {

  departmentId: number | null; departmentName: string | null;
  positionName: string | null; rankName: string | null;

export interface EmployeeInput {
  name: string; phone: string; email: string; birthDate: YmdString;
  status: EmployeeStatus;

}
export interface EmployeeDetail extends EmployeeInput {
  employeeNo: string;
  hasLeaves: boolean;           // 휴가 기록 존재 여부 (삭제 버튼 제어)
}

/* 조직 */
export interface DepartmentNode {
  departmentId: number; parentId: number | null; name: string;
  sortOrder: number; depth: number;      // depth 1 = 회사 바로 아래
  employeeCount: number;                 // 직접 소속 인원 (재직+퇴사)
}
export interface DepartmentTree {
  companyName: string; totalEmployees: number; unassignedCount: number;
  departments: DepartmentNode[];         // parentId, sortOrder 순
}
export interface MasterItem { id: number; name: string; sortOrder: number; employeeCount: number }
export interface MasterInput { id: number | null; name: string }   // null = 신규

/* 회사설정 */
export interface WorkType extends Omit<WorkTypeEntity, 'createdAt' | 'updatedAt'> { employeeCount: number }
export interface WorkTypeInput {
  name: string; kind: WorkTypeKind;
  startTime: HmString | null; endTime: HmString | null; weeklyHours: number;
}
export type Holiday = Omit<HolidayEntity, 'createdAt' | 'updatedAt'>;
export interface HolidayQuery { from: YmdString; to: YmdString }   // 최대 366일
export interface HolidayInput { date: YmdString; name: string }

/* 휴가 */
export interface LeaveQuery {
  leaveType?: LeaveType; departmentIds?: number[]; unassigned?: boolean;
  from?: YmdString; to?: YmdString;      // registeredDate 기준, 둘 다 있으면 최대 366일
  page?: number; size?: number;
}
export interface LeaveRecord {
  leaveId: number; employeeNo: string; employeeName: string; employeeResigned: boolean;
  departmentName: string | null; rankName: string | null;   // 현재 값
  leaveType: LeaveType; registeredDate: YmdString;
  startDate: YmdString; endDate: YmdString; days: number; reason: string | null;
}
export interface LeaveInput {
  employeeNo: string; leaveType: LeaveType;
  startDate: YmdString; endDate: YmdString; reason?: string | null;
}
export interface LeavePreview {
  days: number; year: number;           // year = startDate의 연도
  granted: number; used: number;        // 신규 휴가 제외
  remainingBefore: number; remainingAfter: number; // 음수 가능
}
export interface LeaveGrantQuery {
  year: number; departmentIds?: number[]; unassigned?: boolean;
  keyword?: string; page?: number; size?: number;
}
export interface LeaveGrantRow {
  employeeNo: string; name: string; departmentName: string | null; rankName: string | null;
  hireDate: YmdString; tenure: { years: number; months: number } | null;
  year: number; granted: number; used: number; remaining: number;
  lastGrantedDate: YmdString | null;
}
export interface LeaveGrantInput { employeeNo: string; year: number; amount: number }

## 5. Repository 함수

모든 함수는 `Promise<T>`를 반환한다. "오류"는 `DataError.code`이다.

### 5.1 authRepo / systemRepo

| 함수 | 반환 | 규칙·오류 |
|---|---|---|
| `authRepo.login(req: LoginRequest)` | `Me` | 시드 계정과 `loginId`·`password`가 모두 같아야 한다. 아니면 `AUTH_INVALID_CREDENTIALS`. 성공 시 세션 키 저장 |
| `authRepo.me()` | `Me \| null` | 세션이 없으면 null |
| `authRepo.logout()` | `void` | 세션 키 삭제. 업무 데이터는 유지 |
| `systemRepo.resetDemo()` | `void` | DB를 시드로 교체 |
| `subscribe(listener)` | `() => void` | `storage` 이벤트 구독, 해제 함수 반환 |

로그인 외 모든 Repo 함수는 세션이 없으면 `AUTH_REQUIRED`를 throw한다.

### 5.2 employeeRepo

| 함수 | 반환 | 규칙·오류 |
|---|---|---|
| `list(q: EmployeeQuery)` | `Page<EmployeeListItem>` | 필터: `status`, 부서(`departmentIds`에 속하거나 `unassigned`이고 부서 없음; 둘 다 비면 부서 필터 없음), 검색(이름·이메일은 대소문자 무시 부분일치, 휴대폰은 숫자만 추출해 부분일치). 정렬은 한글 가나다(`localeCompare('ko')`), 동률이면 `employeeNo` 오름차순 |
| `get(no)` | `EmployeeDetail` | `NOT_FOUND` |
| `create(input)` | `EmployeeDetail` | 검증(`01_공통` §6). `departmentId`·`positionId`·`rankId`·`workTypeId`가 존재해야 함(`VALIDATION_FAILED`, 해당 필드). `employeeNo` 자동 채번(`seq.employee`+1, 6자리) |
| `update(no, input)` | `EmployeeDetail` | `employeeNo` 불변. 나머지 `create`와 동일. `NOT_FOUND` |
| `remove(no)` | `void` | 휴가(`leaves`)가 있으면 `EMP_HAS_LEAVES`. 없으면 직원과 해당 `leaveGrants` 삭제. `NOT_FOUND` |
| `moveDepartment(nos: string[], departmentId: number \| null)` | `void` | 대상 직원 전부 존재해야 함, 부서가 존재해야 함(null 허용). 하나라도 실패하면 전체 취소 |

### 5.3 departmentRepo

| 함수 | 반환 | 규칙·오류 |
|---|---|---|
| `list()` | `DepartmentTree` | `depth`는 parent를 따라 계산. `employeeCount` = 직접 소속 인원(재직·퇴사 포함) |
| `create({parentId, name})` | `DepartmentNode` | `parentId`가 null이면 depth 1. 새 depth가 5를 넘으면 `DEPT_DEPTH_EXCEEDED`. 같은 `parentId` 아래 이름(앞뒤 공백 제거, 대소문자 무시) 중복이면 `DEPT_NAME_DUPLICATED`. `sortOrder` = 형제 최대+1 |
| `rename(id, name)` | `DepartmentNode` | 중복 검사(자기 자신 제외). `NOT_FOUND` |
| `remove(id)` | `void` | 하위 부서가 있으면 `DEPT_HAS_CHILDREN`을 **먼저**, 소속 직원이 있으면 `DEPT_HAS_EMPLOYEES`. 삭제 후 형제 `sortOrder`를 1..n으로 재정렬 |
| `move(id, direction: 'UP' \| 'DOWN')` | `void` | 같은 상위 안에서 바로 위/아래 형제와 `sortOrder`를 교환. 이동할 수 없으면 무시(오류 아님) |

### 5.4 positionRepo / rankRepo (동일 시그니처)

| 함수 | 반환 | 규칙·오류 |
|---|---|---|
| `list()` | `MasterItem[]` | `sortOrder` 순. `employeeCount` = 해당 값을 쓰는 직원 수 |
| `saveAll(items: MasterInput[])` | `MasterItem[]` | 이름 1~20자, 앞뒤 공백 제거 후 중복(대소문자 무시)이면 `MASTER_NAME_DUPLICATED`. 기존에 없는 `id`가 오면 `VALIDATION_FAILED`. 배열 순서대로 `sortOrder` 1..n. 배열에 없는 기존 항목은 삭제하고 그 값을 쓰던 직원의 참조를 null로(D19). 전체 한 번에 저장 |

### 5.5 workTypeRepo

| 함수 | 반환 | 규칙·오류 |
|---|---|---|
| `list()` | `WorkType[]` | 정렬: `isDefault` 먼저, 이름 가나다. `employeeCount` 포함 |
| `create(input: WorkTypeInput)` | `WorkType` | 이름 1~20자, 중복(대소문자 무시)이면 `WORKTYPE_NAME_DUPLICATED`. `FIXED`는 시작·종료 필수이고 종료 > 시작, `FLEXIBLE`은 둘 다 null로 저장. 주근무시간 0.5~52, 0.5 단위. `isDefault`=false |
| `update(id, input)` | `WorkType` | 위와 동일(자기 자신 제외 중복 검사). 기본 제공 유형도 수정 가능, `isDefault`는 바뀌지 않음 |
| `remove(id)` | `void` | `isDefault`이면 `WORKTYPE_DEFAULT_PROTECTED`, 적용 직원이 있으면 `WORKTYPE_IN_USE` |

### 5.6 holidayRepo

| 함수 | 반환 | 규칙·오류 |
|---|---|---|
| `list({from, to})` | `Holiday[]` | `from ≤ date ≤ to`, 일자 오름차순. 범위가 366일을 넘거나 `to < from`이면 `VALIDATION_FAILED` |
| `create({date, name})` | `Holiday` | 일자 2000-01-01~2100-12-31, 이름 1~30자. 같은 일자의 휴일(출처 무관)이 있으면 `HOLIDAY_DATE_DUPLICATED`. `type='HOLIDAY'`, `origin='CUSTOM'` |
| `remove(id)` | `void` | `origin='STATUTORY'`이면 `HOLIDAY_STATUTORY_PROTECTED`. `NOT_FOUND` |

### 5.7 leaveRepo

| 함수 | 반환 | 규칙·오류 |
|---|---|---|
| `list(q: LeaveQuery)` | `Page<LeaveRecord>` | `registeredDate` 범위, 휴가구분, 부서(직원의 **현재** 부서) 필터. 정렬: `registeredDate` 내림차순 → `startDate` 내림차순 → `leaveId` 내림차순. 퇴사 직원도 포함(`employeeResigned`) |
| `preview(input: LeaveInput)` | `LeavePreview` | §6 검증을 전부 수행하되 **저장하지 않는다**. 잔여가 음수여도 오류 아님 |
| `create(input: LeaveInput)` | `LeaveRecord` | `preview`와 같은 검증 후 저장. `registeredDate`=오늘. 잔여 초과는 막지 않는다(DD-13) |
| `cancel(leaveId)` | `void` | 휴가 삭제. `NOT_FOUND` |

`preview`/`create` 검증 순서와 오류
1. 필드 규칙: 직원·구분·시작일·종료일 필수, 종료일 ≥ 시작일, 사유 ≤ 200자 → `VALIDATION_FAILED`
2. 직원 존재 → `NOT_FOUND`, 재직중 → 아니면 `LEAVE_EMPLOYEE_NOT_ACTIVE`
3. `HALF`이면 종료일을 시작일로 간주(입력이 달라도 보정)
4. 사용일수 계산(§6) → 0이면 `LEAVE_ZERO_DAYS`
5. 같은 직원의 기존 휴가와 기간이 하루라도 겹치면 `LEAVE_OVERLAP`

### 5.8 leaveGrantRepo

| 함수 | 반환 | 규칙·오류 |
|---|---|---|
| `list(q: LeaveGrantQuery)` | `Page<LeaveGrantRow>` | **재직중 직원만**. 부서·이름(부분일치) 필터. 이름 가나다 정렬. `granted`=해당 연도 부여 합(없으면 0), `used`=시작일 연도가 `year`인 휴가의 `days` 합, `remaining`=granted−used, `lastGrantedDate`=없으면 null |
| `grant({employeeNo, year, amount})` | `LeaveGrantRow` | 직원 재직중이어야 함(`LEAVE_EMPLOYEE_NOT_ACTIVE`). `amount`는 0이 아니고 0.5 배수이며 −99.5~99.5(`VALIDATION_FAILED`, 필드 `amount`). `year` 2000~2100. 새 합계가 0 미만이면 `GRANT_NEGATIVE_TOTAL`. (employeeNo, year) 행이 없으면 생성. `lastGrantedDate`=오늘 |

## 6. 계산 규칙

**휴가 사용일수**
```
HALF  : start가 근무일이면 0.5, 아니면 0           (end는 start로 간주)
ANNUAL: start..end를 하루씩 순회하며
        토·일이 아니고 휴일 마스터(holidays.date)에 없는 날을 센다
근무일 = 토·일이 아니고 휴일 마스터에 없는 날
```
- 주휴일 개념은 없다(M7). 휴일 마스터는 법정·추가 구분 없이 모두 적용한다.
- 휴일 데이터가 없는 연도는 주말만 제외한다.

**잔여**
```
granted(emp, year)  = leaveGrants[emp, year].granted ?? 0
used(emp, year)     = Σ leaves[emp] 중 year(startDate) == year 인 days
remaining           = granted − used
```

**근속**
```
total = (오늘년−입사년)*12 + (오늘월−입사월) − (오늘일 < 입사일 ? 1 : 0)
total < 0 이면 null, 아니면 { years: floor(total/12), months: total % 12 }
```

**페이지네이션**: `totalPages = max(1, ceil(total/size))`, `page`는 1~`totalPages`로 보정.

**정렬 기준**: 문자열은 `localeCompare(a, b, 'ko')`. 날짜는 문자열 비교.
