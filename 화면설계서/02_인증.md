# 02. 인증

## S-AUTH-01 로그인

| 항목 | 내용 |
|---|---|
| 경로 | `/login` (쿼리 `redirect` 선택) |
| 유형 | 페이지(앱 셸 없음) |
| 근거 | D1, M1, M10, M11, DD-19 |
| 범위 | 로그인만. 회원가입·비밀번호 변경·복구·계정 잠금 화면은 없다 |

서버가 없으므로 이 로그인은 **발표 흐름을 위한 데모 화면**이다. 시드된 관리자 계정 1개와 대조하며, 보안 기능이 아니다(`01_공통` §9).

### 와이어프레임

```
+------------------------------------------------+
|                                                |
|           MY 직원관리  [DEMO]                  |
|                                                |
|        아이디                                  |
|        [__________________________]            |
|        비밀번호                                |
|        [__________________________]            |
|                                                |
|        ( 오류 메시지 영역 )                    |
|                                                |
|        [          로그인          ]            |
|                                                |
|  +------------------------------------------+  |
|  | 데모 계정   admin / admin1234            |  |
|  |                        [계정 자동 입력]  |  |
|  +------------------------------------------+  |
|  발표용 데모 — 샘플 데이터만 사용하세요.       |
+------------------------------------------------+
```

### 요소 명세

| 요소 ID | 요소 | 유형 | 규칙 |
|---|---|---|---|
| `login.loginId` | 아이디 | text | 필수, 최대 30자. 진입 시 자동 포커스 |
| `login.password` | 비밀번호 | password | 필수, 최대 100자 |
| `login.error` | 오류 영역 | text | 로그인 실패 시 MSG-101 |
| `login.submit` | [로그인] | button | Enter 키로도 제출 |
| `login.demoHint` | 데모 계정 안내 | box | 아이디·비밀번호를 그대로 표시한다(`admin` / `admin1234`) |
| `login.fillDemo` | [계정 자동 입력] | button | 두 입력칸에 데모 계정 값을 채운다. 제출은 하지 않는다 |

### 동작

| 이벤트 | 결과 |
|---|---|
| [로그인] / Enter | 두 필드가 채워졌는지 확인(미입력 시 해당 필드 아래 MSG-001). 통과하면 `authRepo.login({loginId, password})` |
| 성공 | `redirect` 쿼리가 있고 앱 내부 경로(`/`로 시작, `//` 아님)이면 그곳으로, 아니면 `/employees`로 이동 |
| `AUTH_INVALID_CREDENTIALS` | MSG-101 표시. 비밀번호 필드만 비우고 포커스 이동 |
| 그 외 오류 | 저장소 오류는 MSG-013·014, 나머지는 MSG-007 |
| 진입 시 이미 로그인됨 | `authRepo.me()`가 값을 반환하면 `/employees`로 이동 |

실패 횟수 제한과 계정 잠금은 없다(서버 보안 요소이므로 데모에서 제외, M11).

### 상태

| 상태 | 표시 |
|---|---|
| 초기 | 입력 비어 있음, 오류 영역 숨김 |
| 처리 중 | 버튼 비활성+스피너 |
| 저장소 사용 불가 | 로그인 화면 상단에 MSG-013 배너. [로그인] 비활성 |

### 데이터 계층
`authRepo.login(req)` → `Me`, `authRepo.me()` → `Me | null`, `authRepo.logout()`

### 수용 기준
1. 아이디 또는 비밀번호가 비어 있으면 필드 아래 MSG-001이 표시되고 로그인되지 않는다.
2. [계정 자동 입력] 후 [로그인]하면 `/employees`로 이동하고 헤더에 회사명과 관리자 이름이 표시된다.
3. `/leaves/grants`에서 로그아웃한 뒤 다시 로그인하면(`redirect=/leaves/grants`) `/leaves/grants`로 돌아온다.
4. `redirect=https://example.com` 같은 외부 주소는 무시하고 `/employees`로 이동한다.
5. 잘못된 비밀번호를 몇 번 입력해도 계정은 잠기지 않는다.
6. 아이디가 없는 경우와 비밀번호가 틀린 경우의 오류 문구가 동일하다(MSG-101).
7. 로그인한 상태로 탭을 닫았다 다시 열면 로그인 화면이 나오고, 이전에 입력한 직원·휴가 데이터는 그대로 남아 있다.
