# 04. 휴가관리

휴가관리는 두 탭으로 구성된다. `/leaves`는 `/leaves/records`로 이동한다.

공통 규칙 (이 파일 전체에 적용)
- 휴가는 관리자가 직접 등록하며 등록 즉시 확정된다. 결재 상태·반려사유는 없다(M2).
- 휴가구분은 연차(ANNUAL) / 반차(HALF) 두 가지다. 반차는 0.5일, 하루 단위이며 오전/오후 구분은 없다(DD-10).
- 사용일수 = 시작일~종료일 중 **토·일과 휴일(회사설정)을 제외**한 일수. 반차는 0.5일 고정(M7, 00_인덱스 DD-11·12).
- 사용일수는 등록 시점에 데이터 계층(`leaveRepo`)이 계산해 저장하고, 시작일이 속한 연도에 귀속한다.
- 연도별 잔여 = 해당 연도 부여일수 − 해당 연도 사용일수.

## S-VAC-01 휴가현황·등록 탭

| 항목 | 내용 |
|---|---|

```

[휴가현황·등록] [휴가부여]

| 휴가구분   (•)전체 ( )연차 ( )반차                                              |
| 부서구분   (•)전체 ( )부서별 [부서선택]                                         |
| 등록일자   [1개월][3개월] [2026-09-19] ~ [2026-10-19]                 [조회]    |
+--------------------------------------------------------------------------------+
총 8건                                                          [+ 휴가 등록]
+--------+------+------+------+----------+------------+------------+-----+------+----+
| 이름   | 부서 | 직위 |구분  | 등록일   | 시작일     | 종료일     |일수 | 사유 |    |
+--------+------+------+------+----------+------------+------------+-----+------+----+
| 이지은 |백엔드| 대리 | 연차 |2026-10-19|2026-10-21  |2026-10-22  | 2   | 개인 |[취소]|
| 박현우 |인프라| 과장 | 반차 |2026-10-19|2026-10-23  |2026-10-23  | 0.5 | -    |[취소]|
+--------+------+------+------+----------+------------+------------+-----+------+----+
                                    < 1 >

### 요소 명세

| 요소 ID | 요소 | 유형 | 규칙 |
|---|---|---|---|
| `leave-list.filter.type` | 휴가구분 | radio | 전체(기본) / 연차 / 반차 |
| `leave-list.filter.dept` | 부서구분 | radio+S-CMN-01 | `01_공통` §3.1 패턴, `includeUnassigned=true` |
| `leave-list.filter.period` | 등록일자 | 날짜 범위 | `01_공통` §3.7. 기본값: 종료일 = 오늘, 시작일 = 오늘−1개월. 등록일(휴가를 등록한 날짜) 기준 |
| `leave-list.search` | [조회] | button | 검증 후 1페이지 조회 |
| `leave-list.create` | [+ 휴가 등록] | button | S-VAC-02 열기 |
| `leave-list.table` | 목록 | table | 컬럼: 이름, 부서, 직위, 휴가구분, 등록일, 시작일, 종료일, 일수, 사유, 취소. 기본 정렬: 등록일 내림차순, 같으면 시작일 내림차순 |
| `leave-list.row.cancel` | [취소] | button | 행별. 확인(MSG-404, danger) 후 삭제 |

- 사유가 없으면 `-`, 길면 한 줄 말줄임(마우스 오버 시 전체).
- 퇴사한 직원의 휴가 기록도 목록에 표시한다(이름 옆 "(퇴사)").
- 일수는 `01_공통` §5 형식(0.5, 2 등).
- 수정 기능은 없다. 잘못 등록한 경우 [취소] 후 다시 등록한다.

### 동작

| 이벤트 | 결과 |
|---|---|
| 최초 진입 | 기본 필터로 조회 |
| [조회] | 부서별 선택(MSG-009), 기간(MSG-010·011) 검증 후 조회 |
| [취소] 확인 | `leaveRepo.cancel(leaveId)` → MSG-004, 목록 재조회. 해당 연도 사용일수가 복구된다 |
| S-VAC-02 저장 성공 | 모달 닫고 재조회. 등록 직후 보이도록 필터에 등록일이 포함되지 않는 경우에도 토스트로만 알린다 |

### 상태
`01_공통` §4를 따른다. 필터가 기본값이고 0건이면 "조회 결과가 없습니다." 아래에 "[+ 휴가 등록]으로 휴가를 등록하세요."를 덧붙인다.

### 데이터 계층
`leaveRepo.list(query)` → `Page<LeaveRecord>`, `leaveRepo.cancel(leaveId)`

### 수용 기준
1. 반차 필터로 조회하면 반차 휴가만 나오고 일수는 모두 0.5이다.
2. 목록에서 [취소]를 확인하면 행이 사라지고, S-VAC-03의 해당 직원 사용일수가 줄어든다.
3. 퇴사한 직원의 기존 휴가가 목록에 표시된다.
4. 기간을 367일 이상으로 설정하고 [조회]하면 MSG-011이 표시되고 요청이 없다.
5. 새로고침해도 필터·페이지가 유지된다.

| 사용일수      2일  (주말·휴일 제외)                               |

| `leave-form.endDate` | 종료일* | date | 연차: 필수, 시작일 이상. 반차: 시작일과 같은 값으로 자동 고정되고 비활성 |
| `leave-form.days` | 사용일수 | text 🔒 | 미리보기 결과(`leaveRepo.preview`). 계산 전에는 `-` |
| `leave-form.balance` | 잔여 휴가 | text 🔒 | "{연도}년 잔여 {x}일 → 등록 후 {y}일". 연도 = 시작일 연도 |
| `leave-form.reason` | 사유 | text | 선택, 최대 200자, 글자수 표시 |
| `leave-form.banner` | 배너 | | 중복·0일 등 오류는 빨간 배너, 잔여 초과는 노란 경고 배너 |
| `leave-form.submit` | [등록] | button | 직원·시작일·종료일이 유효하고 미리보기가 성공했을 때만 활성 |

### 동작

| 이벤트 | 결과 |
|---|---|
| 직원·휴가구분·시작일·종료일 중 하나가 바뀌어 4개가 모두 유효 | `leaveRepo.preview(input)` 호출(로컬 계산이므로 디바운스 없이 즉시) → 사용일수·잔여 갱신 |
| 휴가구분을 반차로 변경 | 종료일 = 시작일로 고정·비활성 |
| 종료일 < 시작일 | 종료일 필드에 MSG-010, 미리보기 호출 안 함 |
| 미리보기 `LEAVE_ZERO_DAYS` | 배너 MSG-402, [등록] 비활성 |
| 미리보기 `LEAVE_OVERLAP` | 배너 MSG-401, [등록] 비활성 |
| 미리보기 응답의 `remainingAfter` < 0 | 노란 경고 배너에 MSG-403 문구 표시(`n`=현재 잔여, `m`=사용일수). [등록]은 활성 |
| [등록] | 잔여 초과 경고 상태이면 S-CMN-02(MSG-403)로 한 번 더 확인 → `leaveRepo.create(input)`. 성공 시 MSG-003, 닫기, 목록 재조회 |
| 등록 시 `LEAVE_OVERLAP`/`LEAVE_ZERO_DAYS`/`LEAVE_EMPLOYEE_NOT_ACTIVE` 오류 | 배너에 MSG-401 / MSG-402 / MSG-405. 모달 유지 |

### 수용 기준
1. 금요일~다음 주 월요일 연차를 선택하면 사용일수가 2일(금, 월)로 표시된다(주말 제외).
2. 기간 안에 휴일(회사설정)이 있으면 그 날짜는 일수에서 제외된다.
3. 토요일 하루만 연차로 선택하면 MSG-402가 표시되고 [등록]이 비활성이다.
4. 반차를 고르면 종료일이 시작일과 같아지고 사용일수는 0.5이다. 시작일이 주말·휴일이면 MSG-402.
5. 같은 직원의 기존 휴가와 하루라도 겹치면 MSG-401이 표시된다.
6. 잔여보다 많이 사용하는 기간을 입력하면 경고가 표시되고, 확인 후 등록하면 잔여가 음수(빨간색)로 보인다.
7. 퇴사 직원은 직원 검색 결과에 나오지 않는다.
8. 12월 30일~다음 해 1월 2일 휴가는 사용일수 전체가 12월(시작일 연도)에 귀속된다.

```

[휴가현황·등록] [휴가부여]

전년도 컬럼·계산된 휴가·자동소멸은 없다(M3).

### 동작

| 이벤트 | 결과 |
|---|---|
| [부여] | 클라이언트 검증(MSG-407) → `leaveGrantRepo.grant({employeeNo, year, amount})`. 성공 시 MSG-003, 해당 행의 부여·잔여·최근부여일을 반환값으로 갱신하고 입력칸 비움 |
| `GRANT_NEGATIVE_TOTAL` 오류 | 해당 행 입력칸 아래 MSG-406 |
| 기준연도 변경 | 선택 즉시 재조회(조회 버튼 없이) |
| 입력칸에서 Enter | [부여]와 동일 |

- 동일 행에서 여러 번 부여하면 누적된다(예: 15 부여 후 1 부여 → 16).
- 부여 이력(건별)은 화면에 표시하지 않는다. 합계와 최근부여일만 유지한다(D15).

### 상태
`01_공통` §4를 따른다. 재직중 직원이 없으면 "등록된 재직 직원이 없습니다."를 표시한다.

### 데이터 계층
`leaveGrantRepo.list(query)` → `Page<LeaveGrantRow>`, `leaveGrantRepo.grant(input)` → `LeaveGrantRow`

### 수용 기준
1. 이지은에게 15를 부여하면 부여 15, 잔여가 사용일수 반영 값으로 갱신되고 최근부여일이 오늘이 된다.
2. 같은 행에 1을 더 부여하면 부여가 16이 된다.
3. 부여 합계 15인 직원에게 -16을 입력하면 MSG-406이 표시되고 값은 변하지 않는다.
4. 0 또는 0.3을 입력하면 MSG-407이 표시되고 요청이 없다.
5. 기준연도를 2025로 바꾸면 2025년 부여·사용 기준으로 표시된다.
6. 퇴사 직원은 목록에 나오지 않는다.
7. S-VAC-01에서 휴가를 등록·취소한 뒤 이 탭을 열면 사용·잔여가 반영되어 있다.
