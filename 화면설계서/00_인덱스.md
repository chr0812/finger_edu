**읽는 순서**: 00 → 01 → 90 → 91 → 구현할 화면 파일. 각 화면 파일은 와이어프레임, 요소 명세, 동작, 상태, 검증, 데이터 계층, 수용 기준 순서로 같은 구조를 따른다.

**표기 규칙**
- 요소 ID(예: `emp-list.filter.status`)는 `data-testid`로 그대로 사용한다.
- `*`는 필수 입력, `🔒`는 읽기 전용이다.
- 메시지는 `MSG-nnn`으로 참조하며 문구는 `01_공통.md` §7에 있다.
- `DD-n`은 PRD에 없어 이 설계에서 정한 사항이다(§5).

## 3. 메뉴 구조와 화면 흐름

```
로그인(/login) ──성공──▶ 앱 셸
                         ├─ 직원관리
                         │    ├─ 직원등록  /employees        (목록 → 등록/상세 모달)
                         │    └─ 조직도    /organization     (부서 탭 | 직책/직위 탭)
                         ├─ 휴가관리      /leaves            (휴가현황·등록 탭 | 휴가부여 탭)
                         └─ 회사설정      /settings          (근무유형 탭 | 휴일 탭)
```

**화면 간 의존**
- 직원 등록 폼의 근무유형 선택지는 S-CFG-01, 부서·직책·직위 선택지는 S-ORG-01·04가 원천이다.
- 휴가 일수 계산은 S-CFG-03의 휴일을 사용한다.
- 구현 순서(PRD §7): 회사설정 → 조직도 → 직원등록 → 휴가관리. 인증과 앱 셸은 가장 먼저 만든다.

## 6. 범위 밖 / 구현 단계 전달 사항

- 2026년 법정공휴일 샘플은 `91`에 있으나 **발표 전 공식 자료로 검수**가 필요하다. 제헌절·노동절 지정 여부는 확인하지 못해 시드에서 제외했다.
- 최초 회사·관리자 계정은 시드 데이터로 생성한다(D5). 화면 없음.
- 서버·DB·백엔드 프레임워크·실제 인증은 이 데모의 범위 밖이다. 이후 실서비스로 확장할 때는 Repo 계층의 구현을 서버 API 호출로 교체하면 화면 코드를 유지할 수 있다.
- PRD §1.2 제외 항목(근태, 급여, 사내공지, 직원 계정 등)은 화면·데이터·함수를 만들지 않는다.
- 실제 개인정보는 입력하지 않는다. 브라우저 저장소의 데이터는 암호화되지 않는다.
